# Edit Standup Preferences

This skill edits a single `##` section of the user's standup preferences file in
place, preserving the rest of the file. It exists because `/standup:init`
deliberately refuses in-place edits; init only creates a new preferences file or
fully replaces an existing one. Use this skill for targeted changes like editing the
output-format Template, updating a GitHub username, or switching the destination,
without regenerating the whole file.

## Tone

Confirm the target section, produce the edit, show the diff, apply on confirmation.
Nothing else.

- No narration ("I will now...", "Next I'll...").
- No explanations of what you're doing or why.
- No meta-commentary about the process.
- The only output is any clarifying question, the diff preview, and the final summary.

Invisible work (reading the file, locating the section) happens silently.

## Target

`~/.claude/standup/preferences.md`. Resolve the `~` against the current user's home
directory. This is ALWAYS the target regardless of the current working directory.
NEVER substitute cwd, and NEVER write to `~/.claude/CLAUDE.md` or any other
auto-loaded file.

## Section ↔ module map

Each `##` section in the preferences file maps 1:1 to a `templates/user/` module.
Use this map to identify which section a request targets:

| `##` section              | Source module      | Typical edits                                                                                           |
| ------------------------- | ------------------ | ------------------------------------------------------------------------------------------------------- |
| `## Identity & workspace` | `identity.md`      | Atlassian display name/email, GitHub username, Jira base URL, timezone                                  |
| `## Destination`          | `destination.md`   | Set the destination to any value (`local markdown file`, `stdout to chat`, a path, or any other target) |
| `## Output format`        | `output-format.md` | Edit the concrete report-format text (the section holds a custom template or the written-out default)   |

## Steps

1. **Read the file.** Use `Read` to read `~/.claude/standup/preferences.md`.
   - If it does not exist, STOP and tell the user to run `/standup:init` first; this
     skill edits an existing file and does not create one.

2. **Locate the target section.** From the user's request, identify which `##`
   section to edit using the map above. If the request is ambiguous (could touch
   more than one section), ask a single clarifying question naming the candidate
   sections, then proceed. Do not touch any section other than the one identified.

3. **Apply the change to that section only.** Produce the edited file content by
   changing only the lines inside the target `##` section. Preserve verbatim:
   - Every other `##` section and its content.
   - The generated header block at the top of the file (the `# Standup Preferences`
     title and the `<!-- Generated by standup ... -->` comment).
   - Any `[YOUR-PREFERENCE]` placeholders the user is NOT explicitly changing (a file produced by the current `/standup:init` will have none, but a hand-authored or legacy file may). Never invent a value for a placeholder the user did not supply; leave it verbatim.
   - Blank-line separation between sections.

4. **Diff preview.** Write the edited content to a temp file (e.g.
   `/tmp/standup-prefs-edit-preview-$$.md`) and run
   `diff -u "$HOME/.claude/standup/preferences.md" /tmp/standup-prefs-edit-preview-$$.md`
   via `Bash`; display the diff. If the diff is empty, report that nothing would
   change and STOP.

5. **Confirm.** Use `AskUserQuestion` with options **Apply**, **Show diff again**,
   **Cancel**. On **Show diff again**, redisplay the diff and ask again. On
   **Cancel**, stop without writing and clean up the temp file.

6. **Backup, then write.** Only after an explicit **Apply**:
   - Ensure the directory exists: `mkdir -p "$HOME/.claude/standup"` via `Bash`.
   - Copy the current file to
     `~/.claude/standup/preferences.md.bak-$(date -u +%Y%m%dT%H%M%SZ)` via `Bash` and
     capture the backup path.
   - Use `Edit` to apply the section change to
     `~/.claude/standup/preferences.md` (the file was Read in step 1, so `Edit` is
     viable). Fall back to `Write` with the full edited content only if `Edit`'s
     old-string match fails.
   - Clean up the temp preview file.

7. **Summary.** Report:
   - The target path written.
   - Which `##` section was edited and a one-line description of the change.
   - The backup file path.
   - A reminder that `~/.claude/standup/preferences.md` is load-on-demand (the
     standup skill/agent reads it explicitly at report time; it is NOT auto-loaded
     into other conversations).

## Notes

- **Never write without an explicit Apply confirmation.**
- **Never skip the backup step.** Every write is preceded by a timestamped backup.
- **Edit one section only.** Preserve all other sections, the header block, and
  blank-line separation verbatim.
- Preserve any `[YOUR-PREFERENCE]` placeholders that the user is not explicitly changing (current-init files have none; hand-authored files may). Do not invent values.
- The target is ALWAYS `~/.claude/standup/preferences.md`, regardless of the current
  working directory. NEVER substitute cwd, and NEVER write to `~/.claude/CLAUDE.md`.
